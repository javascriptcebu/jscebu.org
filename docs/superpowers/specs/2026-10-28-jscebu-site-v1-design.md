## 1. Intent

Move www.jscebu.org off Notion and onto the new Astro site now, with what exists today, and add events once Cebby can serve them.

- **[Decided]** "Ship the landing page for now and what's available."
- **[Decided]** Build the site first, then swap all of www.jscebu.org to it.
  - This **supersedes Task 8 of the design-system plan**, which was a `/brand`-only route cutover.
  - There is no partial cutover.

## 2. Goals, non-goals, anti-goals

**Goals**
- A landing page and the few pages the old site really had, all built on the design system.
- www.jscebu.org served by the `jscebu-org` Cloudflare Worker.
- Every old URL lands somewhere sensible.

**Non-goals for v1** (later releases)
- `/events` pages and the Cebby endpoint (§6).
- A Hacktoberfest page (it has its own site).
- Event recaps, RSS, a blog.
- Moving the apex domain off Vercel.
- Auto-deploy from git.

**Anti-goals**
- An old link that now 404s without a reason.
- An API token reaching the browser or the repo.
- Hand-typed colors or fonts. The design-system rules and `check-dist` apply to every page.

## 4. Content model

- **[Decided]** Markdown in the repo, using Astro content collections ("or any new one today").
  - **[Builder]** Use Astro 7's current content-layer API (loaders) and check its docs at build time.
- **[Proposed]** Collections, with schemas validated at build:
  - **`projects`:** one Markdown file per project. Fields:
    - `name`, `url`, `repo?`, `summary`
    - `image` (a local logo or screenshot)
    - `status` (`active` | `archived`)
    - `featured: boolean`
    - `order`
    - Body: a longer description.
  - **`organizers`:** one data file. Fields: `name`, `role`, `community?`, `order`.
  - **`links`:** one data file. Fields: `label`, `url`, `handle?`, `order`.
- `about.md` is a single Markdown page.
- The landing-page copy lives in the page itself.
- **Cebby's card content:** "Cebby is a public discovery layer for Cebu tech events". It links to https://www.getcebby.com and github.com/getcebby/cebby, with its icon copied from the Cebby repo.

## 6. Later: events from Cebby

Recorded so v1 doesn't paint it into a corner. This gets built in its own release.

- **[Decided]**
  - Events come from Cebby's API.
  - Cebby gains an endpoint that returns JS Cebu's events, protected by an API token.
  - jscebu.org pulls it server-side, so the token never reaches the browser or the repo.
- **What exists today in Cebby** (`getcebby/cebby`, `apps/pwa`):
  - Astro 5 on Cloudflare Workers, with server-side rendering.
  - Supabase tables `organizations`, `accounts`, `events`, `event_organizers`.
  - JS Cebu is in the data (`javascript-cebu`).
  - Existing routes live under `src/pages/api/`.
- **[Builder, then]** Fetch at build time with a content loader, or per request with a live collection, which needs the Cloudflare adapter. Decide when building it.
- **[Decided, input for that release]** "We've got lots of events and I don't want to build it in a way that's one list of top to bottom."
  - Dorell shared the Facebook past-events page on 2026-10-28. It holds about 50 events, from Jan 2019 to Oct 2026.
  - **Series:** React Series: Zero to Hero 1–5 plus a hackathon (2019); six AI4Devs Workshops (Jun 2025); Automated Testing workshops (2024–2025).
  - **Hacktoberfest Cebu stages, per edition:** kickoff or opening, online midpoint, deployment day, awarding. Editions ran 2020, 2021, 2023, 2024, 2025 and 2026.
  - **Hosts besides JS Cebu:** React Cebu, Vue.js Cebu, DEVCON Cebu, enspace Cebu, PWA Pilipinas, Cebu Tech Communities.
  - **Recurring venues:** DOST Cebu PSTO, enspace Cebu, LegalMatch, Zero-Ten Park.
  - **Facebook lists some events twice.**
  - The browse design (grouping by year, series or edition, filters, highlights) is decided in that release, not v1.

## 7. Going live

**Before the swap**
- Confirm the jscebu.org zone is in the Cloudflare account wrangler uses (`@dorelljames`).
- Deploy the Worker to workers.dev and check every page and redirect there.
- **[Proposed]** These are the go/no-go gate.

**The swap: [Proposed]**
- Record the current DNS records.
- Delete the `www` CNAME to `cname.vercel-dns.com`.
- Attach `www.jscebu.org` to the `jscebu-org` Worker as a **Workers Custom Domain**. Cloudflare creates the DNS record and the certificate, and there is no origin, so the zone's SSL mode doesn't matter.
- Expect a gap of seconds to minutes between the delete and the attach.
- Needs Dorell's explicit "go".

**After the swap**
- Run the §5 URL matrix against www, plus `/brand.md` headers.

**Rollback**
- Remove the custom domain.
- Recreate the `www` CNAME to `cname.vercel-dns.com`, DNS-only.

**Apex**
- `jscebu.org` keeps its working Vercel `308 → www` for now.
- Retiring Vercel is a follow-up.

**Deploys**
- By hand with `wrangler deploy` for v1.
- **[Proposed]** Connecting Workers Builds for auto-deploy from `main` is a follow-up.

**Branches**
- This work is on `feat/site-v1`, stacked on the design-system PR (#1).
- Its PR targets `feat/brand-v0.1` until #1 merges.
